Discord Voice Grouper

ボイスチャンネルのグループ分け、通話待機、VC集合フォームを扱うDiscord Botです。

できること セットアップ コマンド ボタン募集 Render トラブルシュート

できること

/splitvc
VC参加者を3人組中心にグループ分けし、PB連携や途中参加VCまで処理します。
通話待機
JST固定スロットの定時募集と、VCの開始・終了に合わせた通知を処理します。
ボタン募集
常設パネルから匿名の即時募集を作成し、参加確定・ロール世代管理・VC開始を処理します。

公開募集には作成者名・参加者一覧・ユーザーIDを表示しません。詳細仕様は同梱の README.md を参照してください。

セットアップ

  1. Discord Developer PortalでBotを作成し、Guilds、GuildMembers、GuildMessages、MessageContent、GuildVoiceStatesを有効にします。
  2. Botを招待し、メッセージの送受信、履歴閲覧、メッセージ管理、Manage Roles、VC操作に必要な権限を付与します。
  3. .env.exampleを.envへコピーし、DISCORD_TOKEN、DISCORD_CLIENT_ID、MONGODB_URIを設定します。
  4. npm install、npm run register、npm startの順に実行します。
本番ではBotのロールを call_wait_role と voice_participant_role より上位に置いてください。Bot Tokenは公開しないでください。

コマンドと設定

/setting callwaitで通話待機の共通設定を保存します。

/setting callwait call_wait_enabled:true call_wait_interval_minutes:45 call_wait_role:@通話希望者 call_wait_prompt_channel:募集チャンネル call_wait_notice_channel:集合通知チャンネル call_wait_voice_category:VCカテゴリ otebo_quick_confirm_seconds:30 bosyu_mention_role:@募集通知
設定用途
call_wait_prompt_channel定時募集の送信先と、設定操作の基準チャンネルです。
call_wait_notice_channel常設パネル、匿名募集、成立通知、VC開始通知の送信先です。
call_wait_role定時募集・ボタン募集の成立時に一時付与するロールです。
bosyu_mention_roleボタン募集で「@通話へのメンション」を有効にしたときの通知ロールです。
otebo_quick_confirm_seconds別の参加者が参加希望した後の確認秒数です。省略時は30秒です。

旧来の募集コマンドや、時間を選ぶボタン募集モードは現行コマンドとして登録していません。

ボタン募集

call_wait_notice_channelの最下部に、次の常設パネルを表示します。

下のボタンから募集を作成すると、募集内容と参加ボタンを含む匿名の募集メッセージが送信されます。
参加ボタンが押されると、参加者と募集作成者へ招集メンションが送られます。
成立しなかった募集は自動で削除されます。

パネルの募集を作成から、次を入力します。

  • 掲載終了時刻: JSTの次の15分区切りから2時間後まで
  • 予定通話時間: なし / 30分間 / 1時間
  • @通話へのメンション: しない / する
  • ひとこと: 任意、300文字まで

公開本文は匿名で、公開ボタンは参加希望と募集を取り消すです。参加希望者本人だけに参加をキャンセルを表示します。作成者は初期参加者として扱い、確認時間後にBot以外の参加者が2人以上なら成立通知とロール付与を行います。

<@&通話希望者> 雑談募集が成立しました！VCへの参加お願いします！

成立、掲載終了、VC開始、定時募集との統合、作成者による取消しでは、募集メッセージと一時状態を回収します。ロール解除は世代番号を確認してから行うため、後続の募集のロールを誤って解除しません。

必須環境変数DISCORD_TOKEN、DISCORD_CLIENT_ID、MONGODB_URI
通話待機の主な環境変数PB_CALL_WAIT_ENABLED、PB_CALL_WAIT_ROLE_ID、PB_CALL_WAIT_PROMPT_CHANNEL_ID、PB_CALL_WAIT_NOTICE_CHANNEL_ID、PB_CALL_WAIT_VOICE_CATEGORY_ID、PB_CALL_WAIT_INTERVAL_MINUTES、PB_OTEBO_QUICK_CONFIRM_SECONDS

Renderでは、/settingで保存したサーバー設定を永続化するためMongoDB接続を維持してください。スラッシュコマンド変更後はnpm run registerを再実行します。

トラブルシュート

  • パネルが出ない場合は、Botが通知チャンネルで表示・送信・埋め込み・履歴閲覧・メッセージ管理を持つこと、通知チャンネルとcall_wait_roleが設定済みであることを確認します。
  • 募集成立後にロールが付かない場合は、Botの最上位ロールが対象ロールより上位か、Manage Rolesがあるかを確認します。
  • 成立・VC開始・定時募集の処理中は、競合防止のためパネルが一時的に非表示になります。運用ステータスの募集モジュールで、パネル、募集、ロール世代、クリーンアップ状態を確認できます。
  • 再起動時は確定済み通知を再送しません。不確実な送信状態は自動再送せず、運用ステータスで確認してください。
  • スラッシュコマンドが見えない場合は、npm run registerを実行し、テスト中はDISCORD_GUILD_IDを設定します。
  • /healthが応答しない場合は、RenderのRoot Directory、Build Command、環境変数、MongoDBの許可IPを確認します。
