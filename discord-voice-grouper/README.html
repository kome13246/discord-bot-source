概要

基本

3人組を基本に振り分け

VC内のメンバーを読み取り、3人組を中心にグループ分けします。余りが1人または2人なら既存グループへ寄せ、4人グループを作ります。

PB連携

親VC・子VCへ自動転送

PBの親VCへ代表者を移動し、PBが作成した子VCへ同じグループの残りメンバーを移動します。

運用補助

募集・フォーム・ログ

通話待機、お手軽募集、話題フォーム、提案フォーム、運用ログ、DISBOARD bump通知までまとめて扱います。

グループ分けルール

人数分け方補足
1から2人そのまま小さいグループとして表示します。
3人3基本形です。
4人4余り1人を3人組へ寄せた形です。
5人3 + 23人・4人だけでは作れないため例外です。
6人3 + 32グループです。
7人4 + 3余り1人を1グループへ寄せます。
8人4 + 4余り2人を2グループへ寄せます。
9人以上3人組中心余りが出た場合だけ4人グループを作ります。

最短セットアップ

1. Discordアプリ作成

Developer PortalでApplicationとBotを作り、TokenとClient IDを控えます。

2. Botを招待

Scopesは bot と applications.commands を選びます。

3. .env作成

.env.example をコピーし、TokenやClient IDを入れます。

4. 起動

npm install、npm run register、npm start の順に実行します。

ローカル起動コマンド

copy .env.example .env
npm install
npm run register
npm start

Tokenの扱い: DISCORD_TOKEN はパスワード相当です。GitHubや公開場所へ書かないでください。

必要な権限とIntent

Bot Permissions

  • View Channels
  • Send Messages
  • Add Reactions
  • Read Message History
  • Connect
  • Move Members
  • Manage Roles
  • Manage Channels
  • Set Voice Channel Status

Developer Portalで確認するIntent

  • Server Members Intent: メンバー取得を安定させる場合に確認
  • Message Content Intent: 「話題を出して」など通常メッセージ本文へ反応する場合に必要

参加者ロール、通話希望者ロール、VC集合フォーム用ロールは、Botの最上位ロールより下に置いてください。上にあるロールはBotから付与・解除できません。

  4. Build Commandは npm install、Start Commandは npm start にします。
  5. Environment Variablesへ DISCORD_TOKEN と DISCORD_CLIENT_ID を入れます。

/splitvc

/splitvc は、VC内のメンバーをグループ分けし、PB連携設定が済んでいればVC転送、参加者ロール、終了通知、途中参加受付まで処理します。

/splitvc channel:一般 shuffle:true include_bots:false private:false
オプション省略時説明
channel実行者が入っているVC対象VCです。
shuffletrueランダムに並べ替えます。
include_botsfalseBotユーザーも対象に含めます。
privatefalse結果を自分だけに表示します。

PB連携時の流れ

  1. 振り分け結果を送信します。
  2. 転送前待機後、各グループから1人をPB親VCへ移動します。
  3. PBが作成した子VCを検出します。
  4. 同じグループの残りメンバーを子VCへ移動します。
  5. 参加者ロールを付与します。
  6. 最初の話題と発話順を送信します。
  7. 終了通知、ロール解除、参加お礼メッセージを処理します。
途中参加受付
  • 振り分け完了後、待機VCを自動作成します。
  • 待機VCは10分後、または終了通知キャンセル時に削除します。
  • 3人以下の子VCがあれば、待機中の人を1人補充します。
  • 補充先がない場合、待機VCに3人集まった時点で新規子VCへ転送します。
  • 途中参加者のロール解除は、最初の参加者と同じタイミングで一括処理します。

話題・告知

/kokuchi は会話練習会の告知を送信し、話題リストから最初の話題をランダムに選びます。全話題が一巡するまでは重複しません。

/kokuchi weekday:火曜日 overview_channel:#概要 channel:#告知 send_topic:true

話題管理

  • /addwadai content:好きな季節は？ で追加します。
  • /showwadai で一覧を表示します。
  • /delwadai target:2 で削除します。

/kokuchi で選ばれた話題は、次の /splitvc 後の最初の話題にも使われます。send_topic:false を選んだ場合は、その回の告知にも次回 /splitvc 後にも最初の話題を送りません。20:30には「30分前です！ぜひご参加ください！」を告知送信先へ送り、20:40には集合VCのeveryone接続権限を許可します。

フォーム

話題提供、提案・要望、相談・苦情の3種類を設置できます。相談・苦情だけ、設定したモデレーターロールへメンションします。

/setting forms form_channel:#フォーム設置先 form_send_channel:#フォーム転送先 moderator_role:@モデレーター
/setupforms
フォーム用途転送形式
話題提供会話練習会の最初の話題候補送信者、分類、内容
提案・要望サーバーやBotへの提案送信者、分類、内容
相談・苦情対人トラブルや苦情モデレーターロール、送信者、分類、内容

/b 募集

/b は募集メッセージを送信します。同じユーザーは15分以内に連続使用できません。送信後15分間は、募集内容を編集できます。

/setting bosyu bosyu_channel:#募集チャンネル bosyu_mention_role:@募集通知
/b note:遠慮せずご参加ください！ time:30分 purpose:雑談
  • note は必須です。
  • time は任意です。
  • purpose を指定し、実行者がVCにいる場合、そのVC名を更新しようとします。

VC集合フォーム

対象PB子VCまたは監視VCに2人以上集まったときに開始し、参加者ロール付与と話題フォーム付き集合メッセージを送ります。

  • 2人未満になっても、5分以内に戻れば継続します。
  • 2人未満になって10分後、集合メッセージと話題フォームを削除します。
  • 話題フォームの内容は、送信者が参加中のVCチャンネルステータスへ 今の話題：入力内容 として設定します。
  • 対象カテゴリ内のVC単体で6人以上になると、自動振り分け提案を送ります。

通話待機システム

毎時ちょうどに、1時間後の雑談希望者を募集します。リアクション式またはボタン式を選べます。

/setting callwait call_wait_enabled:true call_wait_role:@通話希望者 call_wait_prompt_channel:#募集 call_wait_notice_channel:#集合通知 call_wait_voice_category:雑談VCカテゴリ call_wait_mode:button call_wait_bosyu_notice_enabled:true
/sendcallwait
ボタン式の流れ
  1. 10:00に、11時から雑談希望の募集ボタンを送ります。
  2. 11:00時点で2人以上が希望していれば、希望者へロールを付与します。
  3. 指定VCカテゴリ内で2人以上の参加を確認してから集合通知を送ります。
  4. 30分後、VCに2人未満なら次回募集を送ります。
募集を出さない条件

call_wait_voice_category 内にBot以外の参加者が2人以上いる場合、募集は出さず、募集送信先へ「複数人が雑談中なので〇時の募集は出ません」と送ります。

お手軽募集システム

/sendotebo で、ユーザーが自分で募集を作成できるボタンを設置します。作成された募集は call_wait_notice_channel へ投稿されます。

/sendotebo

指定した時間になったら

  • 募集者本人は参加予定者に含まれます。
  • 本文に現在の参加予定者数を表示し、増減時に更新します。
  • 他の人が参加予定ボタンを押します。
  • 参加を取り消す場合は、募集メッセージ下の参加キャンセルボタンを押します。
  • 指定時刻に2人以上ならロール付与と集合通知を行います。
  • 2人未満なら募集メッセージを削除します。

人が集まったらすぐ

  • 募集本文に掲載終了時刻を表示します。
  • 参加希望ボタンが押されたら、指定秒数だけキャンセルできます。
  • キャンセル猶予中の一時メッセージは残り秒数を毎秒更新します。
  • キャンセルされなければ、すぐ集合メンションします。
  • 掲載終了まで参加希望がなければ削除します。

募集作成者も参加予定者の一人として扱います。参加予定者が0人になった場合のみ募集メッセージを削除します。会話時間が選ばれている募集では、集合通知後20分以内に対象者が最初に2人以上集まったVCへ 会話時間：30分(予定) または 会話時間：1時間(予定) を設定し、会話時間 + 15分後に空へ戻します。

DISBOARD bumpリマインド

DISBOARDのbump成功メッセージを検知し、2時間後に「前回のbumpから2時間が経過しました」と通知します。現在の仕様ではbump実行者へのメンションは行いません。

よくあるトラブル

/splitvc や /setting が出てこない
  • npm run register を実行してください。
  • DISCORD_CLIENT_ID と DISCORD_GUILD_ID が正しいか確認してください。
  • Bot招待時に applications.commands Scopeが入っているか確認してください。
Renderで package.json が見つからない

RenderのRoot Directoryがずれています。親フォルダごとpushした場合は discord-voice-grouper をRoot Directoryに指定します。

PBの子VCを検出できない

/setting splitvc child_category:... でPB子VCカテゴリを指定してください。Botがそのカテゴリを閲覧できることも確認します。

ロールを付与できない

BotにManage Roles権限があり、対象ロールがBotの最上位ロールより下にあるか確認してください。

Botが起動しない
  • DISCORD_TOKEN is required.: 環境変数にTokenがありません。
  • Cannot find module: npm install が実行されていない可能性があります。
  • ENOENT package.json: RenderのRoot Directoryがずれています。

運用メモ

  • Render無料プランはスリープや再起動の影響を受けます。安定運用が必要なら常時起動環境を検討してください。
  • /setting で保存した data/settings.json は、永続ディスクがない環境では再デプロイで消えることがあります。
  • 確実に残したい設定は、可能な範囲でRenderのEnvironment Variablesへ入れてください。
  • コマンド定義を追加・変更した場合は npm run register が必要です。
  • Botの公開URL確認には /health を使います。
